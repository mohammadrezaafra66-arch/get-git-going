## هدف
افزودن یک دکمه‌ی اختصاصی به صفحه «جستجوی سریع فروش» (`/sales/search`) که با یک کلیک، **همه محصولات برچسب‌دار** را با **نوع قیمت انتخاب‌شده توسط کاربر** نمایش دهد. این دکمه دو حالت دارد: «همه برچسب‌ها» و «انتخاب برچسب خاص». نتایج فقط شامل محصولات موجود/محدود خواهند بود و **بدون سقف ۲۰ تایی فعلی**، با صفحه‌بندی کامل تا آخرین محصول قابل مرور باشند.

## رفتار محصول

- در نوار بالای صفحه (کنار انتخابگر «نوع قیمت فروش») یک دکمه‌ی جدید اضافه می‌شود:
  - عنوان: «نمایش محصولات برچسب‌دار»
  - کلیک ساده روی دکمه → حالت «همه برچسب‌ها» را فعال می‌کند (تمام برچسب‌های قابل‌مشاهده برای نقش کاربر).
  - یک Dropdown کنارش (آیکون فلش) → باز شدن منوی انتخاب چندتایی برچسب‌ها برای حالت «انتخاب برچسب خاص».
- وقتی این حالت فعال شد:
  - شرط حداقل ۲ کاراکتر برای جستجو **دور زده می‌شود** (چون فیلتر برچسب کافی است).
  - فیلتر موجودی به‌صورت قطعی روی «موجود + محدود» قفل می‌شود (بدون توجه به انتخاب قبلی کاربر).
  - نوع قیمت نمایشی همان `salePriceTypeId` انتخاب‌شده در بالای صفحه است؛ تغییرش بلافاصله ستون قیمت همه ردیف‌ها را به‌روز می‌کند.
  - یک Badge فعال «حالت برچسب‌دار» بالای جدول نمایش داده می‌شود با دکمه «خروج از این حالت» برای بازگشت به جستجوی عادی.
- زیر جدول، صفحه‌بندی کامل اضافه می‌شود (قبلی/بعدی + شماره صفحه + تعداد کل) تا کاربر بتواند کل محصولات برچسب‌دار را — هرچقدر که هستند — مرور کند.

## جزئیات فنی

### ۱) State و URL
- یک state جدید `labelMode: "off" | "all" | "selected"` در کامپوننت صفحه.
- یک state `labelModePage: number` برای صفحه فعلی در حالت برچسب‌دار.
- جهت پایداری و قابلیت اشتراک لینک، از search params با `zodValidator` استفاده می‌کنیم:
  - `lm` (label mode): `"off" | "all" | "selected"` با fallback `"off"`.
  - `lp` (page): عدد ≥ ۱، fallback ۱.
  - `pt` (price type id): اختیاری، تا انتخاب نوع قیمت هم در URL بماند.
  - `lids` (selected label ids): آرایه‌ای از رشته‌ها برای حالت `selected`.
- با تغییر هر فیلتر، `lp` به ۱ ریست می‌شود.

### ۲) RPC و Pagination
- RPC موجود `get_sales_search_products` همین الان `p_label_ids`, `p_only_with_price`, `p_limit`, `p_offset` را پشتیبانی می‌کند.
- در حالت برچسب‌دار:
  - اگر `lm="all"` → `p_label_ids` = آرایه‌ی همه `id` برچسب‌های قابل‌مشاهده برای نقش جاری (که از queryی موجود `product-labels-lite-sales` می‌آید و قبلاً با `canSeeInternalLabels` فیلتر شده).
  - اگر `lm="selected"` → `p_label_ids` = `lids` انتخابی کاربر.
  - `p_stock_status` = حذف می‌شود؛ ولی برای رعایت «فقط موجود/محدود»، چون RPC فقط یک مقدار می‌گیرد، یک پارامتر جدید مدنظر نیست. در عوض، فیلتر سمت کلاینت فقط برای حالت «همه» (که ممکن است هر دو وضعیت بیاید) از همان RPC با `p_stock_status=undefined` استفاده می‌کنیم و بعد در کلاینت `stock_status in ("available","limited")` را فیلتر می‌کنیم. اگر RPC در آینده چندوضعیتی شد، می‌توان به سمت سرور منتقل کرد.
  - برای اینکه «همه محصولات» دیده شوند:
    - `p_limit` = `LABEL_PAGE_SIZE` (مثلاً ۵۰).
    - `p_offset` = `(labelModePage - 1) * LABEL_PAGE_SIZE`.
- برای دانستن «تعداد کل»، یک Query کوچک جداگانه با همان فیلترها فقط برای شمارش اجرا می‌کنیم:
  - چون RPC فعلی count برنمی‌گرداند، یک شمارش سبک سمت کلاینت با `supabase.from("products").select("id", { count: "exact", head: true })` و join روی `product_label_assignments` می‌زنیم. شرط‌ها: `is_active=true`, `stock_status in ("available","limited")`, و `label_id in (...)`.
  - این کوئری cache می‌شود (staleTime 60s) و فقط برای محاسبه تعداد صفحات استفاده می‌شود.

### ۳) UI
- در همان `Card` بالای صفحه، یک ردیف جدید اضافه می‌شود:
  - دکمه `Button` با آیکون `Tag` و متن «نمایش محصولات برچسب‌دار».
  - یک `DropdownMenu` کنارش با گزینه‌های:
    - «همه برچسب‌ها» (پیش‌فرض)
    - فهرست برچسب‌های قابل‌مشاهده با Checkbox برای انتخاب چندتایی (روی تأیید → `lm="selected"`, `lids=[...]`).
- وقتی `lm !== "off"`: یک نوار وضعیت بالای جدول:
  - Badge: «حالت برچسب‌دار: همه» یا «حالت برچسب‌دار: ۳ برچسب»
  - متن: «نوع قیمت: {salePriceTypeTitle}» (همان انتخاب کاربر)
  - دکمه `X` با متن «خروج از این حالت» → `lm="off"`.
- زیر جدول: کامپوننت Pagination ساده (قبلی/بعدی + «صفحه X از Y» + «نمایش N از Total»). از همان الگوی `AminHozoorPriceBoard` استفاده می‌کنیم برای یکنواختی.

### ۴) رعایت قوانین پروژه
- هیچ Realtime اضافه نمی‌شود (طبق راهنما realtime فقط در موارد ضروری).
- جستجو همچنان `useDebounce` دارد (بدون تغییر).
- RBAC: همان `requirePermission("sales", "view")` فعلی کافی است؛ visibility برچسب‌ها (internal) با همان منطق موجود (`canSeeInternalLabels`) قبل از ارسال به RPC اعمال می‌شود تا کاربر غیرمدیر برچسب‌های داخلی نبیند.
- analytics: برای ردیف‌های نمایش‌داده‌شده، `trackProductInteraction` با `source: "sales_search"` و یک `eventType: "search_result_viewed"` (همان موجود) فراخوانی می‌شود؛ event جدیدی اضافه نمی‌کنیم.
- timeout/درخواست‌ها: همان React Query پیش‌فرض پروژه؛ تغییری لازم نیست.

### ۵) تغییرات در فایل‌ها
- ویرایش: `src/routes/_app.sales.search.tsx`
  - افزودن `validateSearch` با Zod (`lm`, `lp`, `pt`, `lids`) به `createFileRoute`.
  - افزودن state/derived برای حالت برچسب‌دار، canSearch جدید (در حالت برچسب‌دار همیشه true).
  - شاخه‌بندی `productsQuery`: اگر `lm !== "off"` → پارامترهای جدید + pagination.
  - افزودن `labelModeCountQuery` برای شمارش کل.
  - افزودن UI دکمه + DropdownMenu + نوار وضعیت + Pagination.
- بدون تغییر در دیتابیس / RPC / migration.

## خارج از محدوده (در این فاز انجام نمی‌شود)
- اضافه کردن گروه‌بندی محصولات بر اساس برچسب در همین صفحه.
- ساخت صفحه‌ی جداگانه‌ی «محصولات هر برچسب».
- تغییر RPC برای پشتیبانی از چندوضعیتی موجودی یا برگرداندن count (در صورت نیاز در فاز بعد).
- export به CSV از این حالت.

## ریسک‌ها
- شمارش کل با کوئری جداگانه: اگر تعداد برچسب‌ها/محصولات خیلی زیاد باشد، ممکن است این count کند شود. در صورت بروز، می‌توان آن را به یک RPC جدید `count_sales_search_products` منتقل کرد (فاز بعد).
- اگر RPC در حال حاضر برچسب‌های داخلی را هم در نتایج برمی‌گرداند، نمایش آن‌ها به کاربر بدون مجوز ممکن است نشتی اطلاعات شود. در ارسال `p_label_ids` فقط idهای visible را می‌فرستیم؛ ولی ستون labels در ردیف‌ها همچنان از RPC می‌آید. این رفتار تغییر نمی‌کند چون قبلاً هم همین‌طور بوده و در محدوده این فاز نیست.

## تست دستی پس از پیاده‌سازی
1. ورود به `/sales/search` → دیدن دکمه جدید کنار انتخاب نوع قیمت.
2. کلیک روی دکمه → فعال شدن «حالت برچسب‌دار: همه»، نمایش محصولات برچسب‌دار موجود/محدود با نوع قیمت پیش‌فرض.
3. تغییر «نوع قیمت فروش» از بالا → ستون قیمت همه ردیف‌ها به‌روز شود.
4. باز کردن Dropdown دکمه → انتخاب ۲ برچسب → فقط محصولات با آن دو برچسب نمایش داده شوند.
5. صفحه‌بندی: رفتن به صفحه ۲/۳/... و بازگشت.
6. کپی URL در تب جدید → همان حالت برچسب‌دار، همان صفحه، همان نوع قیمت بازسازی شود.
7. ورود با کاربری بدون نقش admin/manager → برچسب‌های internal در منوی Dropdown دیده نشوند و در `p_label_ids` ارسال نشوند.
