## What this release contains

This release ships production's own code plus the sales-desk line (caller-ID preferences, work
taxonomy, product label filter, person-merge paging and suggestions), the collaboration module
(hub, sidebar pin, inquiry SLA tick), and the nine sales-desk fixes (ticket close/reopen history,
required supplier on purchases, quote-from-deal, activity reminders, no-activity filter).

## How `decided-migrations.txt` participates

`release/config/decided-migrations.txt` is defence-in-depth only (`apply-release-engine.sh:19-25`).
When `-Decided` is passed, the engine **refuses** a `mig_apply` for a version declared `SKIP`, and
re-checks the guard of a `LEDGER_ONLY` version on the real target before writing the ledger row.

None of the 22 G3 versions appear in that file (it still holds only OG-J SKIP 449/450/452 and
OG-C LEDGER_ONLY 373). This release does **not** edit `decided-migrations.txt`. Pass the same file
to `apply-release.ps1 -Decided` as previous releases did.

`ledger_insert_only` is **not** used below. G3 executed every one of the 22 files (`exit=0` in
`g3-apply-results.txt`). The engine requires `ledger_insert_only` only for a decided LEDGER_ONLY
row or an applied-but-unrecorded case whose SQL must not be re-run; none of these 22 are in
`decided-migrations.txt`. Version `20260922192015` (578) was "new on copy" with objects already
on production; G3 still ran the SQL (`new-or-changed`, 829 ms), so the executing directive is
`mig_apply`, not a ledger-only write.
