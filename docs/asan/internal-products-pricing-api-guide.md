# راهنمای ساده — API داخلی محصولات و قیمت‌ها

این یک آدرس اینترنتی (endpoint) است که **فقط می‌خواند** و لیست همهٔ محصولات را همراه با
**همهٔ قیمت‌هایشان** به تو می‌دهد. برای استفادهٔ شخصی خودت و اسکریپت‌های داخلی ساخته شده،
نه برای مشتری، نه برای سایت، نه برای هیچ سرویس بیرونی.

> **هیچ‌وقت با این API نمی‌شود چیزی نوشت یا پاک کرد.** حتی اگر بخواهی هم نمی‌شود —
> در سطح دیتابیس اجازه‌اش را ندارد.

---

## ۱. آدرس‌ها

| چه می‌خواهی | آدرس |
|---|---|
| هر محصول با همهٔ قیمت‌هایش (توصیه‌شده) | `http://192.168.170.8:9000/rest/v1/api_products_pricing` |
| جدول تخت: هر ردیف = یک محصول + یک نوع قیمت | `http://192.168.170.8:9000/rest/v1/api_product_price_rows` |

اولی برای وقتی است که می‌خواهی یک محصول را کامل ببینی.
دومی برای وقتی است که می‌خواهی همه را در اکسل بریزی.

## ۲. احراز هویت — کجا کلید را بگذاری

هر درخواست **دو هدر** لازم دارد:

| هدر | مقدار | نقشش چیست |
|---|---|---|
| `apikey` | مقدار `APIKEY` از فایل اعتبارنامه | فقط برای رد شدن از دروازهٔ Kong |
| `Authorization` | `Bearer ` + مقدار `TOKEN` از فایل اعتبارنامه | **کلید اصلی.** این تعیین می‌کند تو چه چیزی را می‌توانی ببینی |

```

```

داخل آن دو خط `APIKEY=...` و `TOKEN=...` هست.

**اگر توکن لو رفت یا خواستی عوضش کنی:**

```powershell
pwsh deploy\lan\scripts\issue-products-api-credential.ps1
```

یک توکن تازه می‌سازد و همان فایل را به‌روز می‌کند. اگر می‌خواهی توکن قدیمی **فوراً** از کار
بیفتد، باید نقش دیتابیس را حذف کنی (`docs/verification/334-down.sql`) — چون توکن تا تاریخ
انقضایش (۱۰ سال) معتبر می‌ماند.

## ۴. هر فیلد یعنی چه

### ۴.۱ خودِ محصول

| فیلد | یعنی چه |
|---|---|
| `product_id` | شناسهٔ یکتای محصول |
| `sku` | کد محصول (همانی که در سیستم می‌بینی) |
| `name` | نام محصول |
| `brand` / `category` | برند و دسته‌بندی |
| `product_type` | داخلی یا خارجی |
| `stock_status` | وضعیت موجودی: موجود / محدود / ناموجود / نامشخص |
| `product_status` | وضعیت خودِ کالا: فعال / غیرفعال / منسوخ |
| `product_is_active` | آیا محصول در سیستم فعال است |
| `base_currency` | ارز پایهٔ محصول (تومان / دلار / درهم) |
| `color`, `capacity`, `model`, `primary_spec`, `barcode` | مشخصات فنی |
| `accounting_code`, `torob_url` | کد حسابداری و لینک ترب |
| `product_updated_at` | آخرین بار که خودِ محصول (نه قیمتش) ویرایش شد |

### ۴.۲ `purchase_price` — قیمت خرید

**این حساس‌ترین بخش خروجی است.** قیمت تمام‌شدهٔ خودت است.

| فیلد | یعنی چه |
|---|---|
| `amount` | قیمت خرید، به همان ارزی که ثبت شده |
| `currency` | ارز آن قیمت خرید |
| `amount_toman` | همان قیمت خرید، تبدیل‌شده به تومان |
| `currency_rate_used` | نرخ ارزی که موتور قیمت‌گذاری واقعاً استفاده کرده (مثلاً هر دلار ۱۷۴٬۶۰۰ تومان) |
| `effective_at` / `expires_at` | از چه تاریخی معتبر است و تا کِی |

اگر `null` بود یعنی این محصول **قیمت خرید فعالِ معتبری ثبت‌شده ندارد**.

> نرخ ارز داخل `currency_rate_used` **نرخ لحظه‌ای بازار نیست** — نرخی است که موتور
> در همان لحظهٔ محاسبهٔ قیمت استفاده کرده. اگر نرخ دلار بعد از آن عوض شده باشد، تا وقتی
> قیمت‌ها دوباره محاسبه نشوند، این عدد قدیمی می‌ماند.

### ۴.۳ `price_bounds` — کف و سقف قیمت

| فیلد | یعنی چه |
|---|---|
| `min_price` | **کف قیمت** — پایین‌ترین قیمت فروشِ اعلام‌شده در میان انواع قیمت فعال |
| `max_price` | بالاترین قیمت فروش اعلام‌شده |
| `cap_price` | سقف مجاز = `max_price` × ۱٫۰۵ (یعنی ۵٪ بالاتر از بالاترین قیمت) |
| `has_any` | آیا اصلاً قیمت اعلام‌شده‌ای برای این محصول وجود دارد |

این همان اعدادی است که خودِ سیستم موقع صدور پیش‌فاکتور برای کنترل قیمت فروشنده استفاده
می‌کند — از همان تابع مشترک خوانده می‌شود، پس هیچ‌وقت با آنچه در اپ می‌بینی فرق نمی‌کند.

### ۴.۴ `sale_prices` — همهٔ قیمت‌های فروش

یک لیست است. برای هر محصول چند ردیف دارد:

- **ردیف‌های پایه:** برای هر سه نوع قیمت فعال — **نقدی**، **چکی**، **همکاری** —
  حتی اگر هنوز قیمتی نداشته باشند (آن وقت `has_price` می‌شود `false` و مقادیر `null`).
- **ردیف‌های تسویه:** برای هر ترکیب «نوع قیمت × نوع تسویه» که واقعاً قیمت دارد
  (مثلاً «نقدی + تسویه ۲روزه»، «همکاری + سایت»).

| فیلد | یعنی چه |
|---|---|
| `sale_price_type_code` / `_title` | کدام نوع قیمت: `cash_price` نقدی، `cheque_price` چکی، `partner_price` همکاری |
| `settlement_type_code` / `_title` | کدام نوع تسویه. اگر `null` باشد یعنی **قیمت پایه**، بدون در نظر گرفتن مدت تسویه |
| **`current_price`** | **قیمت فعلی — همان عددی که در جستجوی فروش اپ می‌بینی.** گرد‌شده |
| `final_sale_price` | همان قیمت، ولی **قبل از گرد کردن** (خام) |
| `announced_price` | آخرین قیمتی که برای این محصول **ثبت/اعلام** شده (تاریخچهٔ قیمت) |
| `previous_price` | قیمت **قبلی** — برای اینکه ببینی گران شده یا ارزان |
| `last_updated_at` | آخرین بار که این قیمت ثبت شد |
| `purchase_price_toman` | قیمت خریدی که مبنای این محاسبه بوده (تومان) |
| `shipping_cost` | هزینهٔ حمل که به قیمت اضافه شده |
| `margin_amount` | سود — یعنی `current_price` منهای (خرید + حمل) |
| `pricing_rule_id` | کدام قاعدهٔ قیمت‌گذاری این عدد را ساخته |
| `computed_at` | چه زمانی موتور این قیمت را محاسبه کرد |
| `computed_source` | این محاسبه از کجا آمد (مثلاً `workbench_save`، `batch_publish`) |
| `has_price` | آیا این ردیف اصلاً قیمت دارد یا خالی است |

**فرق `current_price` با `announced_price`:**
`current_price` خروجی موتور قیمت‌گذاری است (همانی که اپ نشان می‌دهد).
`announced_price` آخرین چیزی است که در تاریخچهٔ قیمت ثبت شده.
معمولاً یکی‌اند؛ اگر فرق داشتند یعنی موتور دوباره حساب کرده ولی هنوز ثبت/اعلام نشده.

### ۴.۵ فیلدهای پایانی

| فیلد | یعنی چه |
|---|---|
| `prices_last_updated_at` | تازه‌ترین تغییر قیمت در میان همهٔ قیمت‌های این محصول |
| `generated_at` | لحظه‌ای که همین پاسخ ساخته شد (داده کش نمی‌شود، همیشه زنده است) |

## ۵. فیلتر و مرتب‌سازی

می‌توانی هر فیلدی را فیلتر کنی (سبک PostgREST):

```bash
# فقط محصولات موجود
...?stock_status=eq.available

# فقط محصولاتی که قیمت خرید دارند
...?purchase_price=not.is.null

# جستجوی نام
...?name=ilike.*کولر*

# مرتب‌سازی و صفحه‌بندی
...?order=name.asc&limit=50&offset=0

# فقط چند ستون
...?select=sku,name,sale_prices
```

روی جدول تخت هم همین‌طور:

```bash
# فقط قیمت نقدی پایه، فقط ردیف‌هایی که قیمت دارند
".../api_product_price_rows?sale_price_type_code=eq.cash_price&settlement_type_code=is.null&has_price=is.true"
```

خروجی CSV به‌جای JSON:

```bash
curl -s ".../api_product_price_rows?has_price=is.true" \
  -H "apikey: <APIKEY>" -H "Authorization: Bearer <TOKEN>" \
  -H "Accept: text/csv" -o prices.csv
```

## ۷. نکات امنیتی — کوتاه ولی مهم

1. **این توکن قیمت خرید تو را نشان می‌دهد.** هر کسی که آن را داشته باشد، سود تو روی هر
   محصول را می‌بیند. مثل رمز بانک با آن رفتار کن.
2. **هرگز داخل گیت، فرانت‌اند، یا فایل `.env` ریپو نگذارش.** فایل اعتبارنامه عمداً بیرون
   از ریپو ساخته می‌شود.
3. این توکن **فقط** به همین دو آدرس دسترسی دارد. تست شد: با همین توکن، خواندن جدول‌های
   خام `products` و `purchase_prices` هر دو با خطای «permission denied» رد می‌شوند.
4. اگر توکن را عوض کردی، توکن قدیمی **خودبه‌خود باطل نمی‌شود**. برای باطل‌کردن فوری، نقش
   دیتابیس را با `docs/verification/334-down.sql` حذف کن.
5. این آدرس روی شبکهٔ داخلی (`192.168.170.8`) است. آن را به اینترنت باز نکن.
