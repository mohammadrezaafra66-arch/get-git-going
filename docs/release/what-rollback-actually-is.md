# بازگشت واقعی این انتشار — بازتعریف صادقانه

۲۰۲۶-۰۹-۰۳ · جایگزین جملهٔ «خاموش‌کردن پرچم و rebuild» که برای انتشار به‌عنوان یک کل **غلط** بود.

## چرا این سند لازم شد

`src/lib/feature-flags.ts:8-9` می‌گوید: «بازگشت هر چیزی که اینجا گارد شده، یک تغییر زمان‌استقرار
است نه revert کد.» آن جمله برای آنچه *گارد شده* درست است. ولی اندازه‌گیری نشان داد **فقط یک فایل**
در کل `src/` پرچم را import می‌کند، و تقریباً نیمی از تغییر کاربردیدنی پشت هیچ پرچمی نیست.

## هر بخش بی‌پرچم — می‌ماند یا زیر پرچم می‌رود

| بخش | تصمیم | چرا |
|---|---|---|
| **چک‌باکس تعهد داخل دیالوگ** | 🔴 **زیر پرچم رفت** | با پرچم `GUEST_COMMITMENT` خاموش، این هم خاموش می‌شود. اگر نمی‌رفت، خاموش‌کردن پرچم چک‌باکس را **جابه‌جا** می‌کرد نه حذف — همان طراحی ضعیف‌تری که کامنت خود فایل علیهش استدلال می‌کند. **انجام شد.** |
| برچسب «مهمان» + فیلتر سه‌حالته در فهرست | 🟢 **می‌ماند** | فقط خواندنی و نمایشی. فیلتر پیش‌فرض `__all` است، پس رفتار فعلی فهرست عوض نمی‌شود؛ فقط یک ستون انتخاب اضافه می‌شود. پرچم اضافه نمی‌کنیم. |
| بلوک «مسیر استثنا» در صفحهٔ جزئیات | 🟢 **می‌ماند** | فقط خواندنی. تنها وقتی رندر می‌شود که سند استثنا داشته باشد؛ اسناد بدون استثنا هیچ تغییری نمی‌بینند. این همان چیزی است که دادهٔ گام ۳ را از حالت «فقط‌نوشتنی» درمی‌آورد. |
| برچسب‌های فارسی نوع استثنا | 🟢 **می‌ماند** | یک `Record` ثابت. بدون آن، صفحهٔ جزئیات کلید انگلیسی خام نشان می‌داد. |
| بن‌بست `guest_no_link` در `findCreditBlocker` | 🟢 **می‌ماند، عمداً** | هدف اصلی ۴۲۰ همین بود: پایان‌دادن به ثبت سند بدون پرونده زیر برچسب دروغینِ «تأیید حسابداری». این مستقل از تعهد ارزش دارد. |
| تلمتری رد شدن‌ها (`recordRefusal` ×۴) | 🟢 **می‌ماند** | آتش‌کن‌وفراموش‌کن ساختاری: `void`، هرگز `await` نمی‌شود، شکستش فقط `console.error` است. نمی‌تواند کاربر را متوقف کند. و بدون آن، هیچ عددی از ردها نداریم. |
| انتخابگر مشتری | 🟢 **می‌ماند** | از قبل وجود داشت؛ این انتشار دست نزده. |

## بازگشت واقعی این انتشار، دقیقاً

سه لایهٔ مستقل، از سبک به سنگین:

### لایهٔ ۱ — تعهد را بردار (بدون revert، بدون مایگریشن)

```powershell
# در deploy/lan/.env.lan مقدار را خالی کن (یا خطش را بردار)
#   VITE_FEATURE_QUOTE_GUEST_COMMITMENT=
$env:GIT_SHA = (git rev-parse --short HEAD); $env:BUILD_TIME = (Get-Date -Format o)
docker compose --env-file deploy/lan/.env.lan -f deploy/lan/docker-compose.yml up -d --no-deps --build web
```

**اثر:** چک‌باکس از فرم و از دیالوگ می‌رود. ثبت مهمان دقیقاً به سادگی امروز می‌شود.
**نمی‌برد:** برچسب مهمان، فیلتر، نمایش استثنا، تلمتری، و خودِ `guest_no_link`.

### لایهٔ ۲ — انتخابگر را هم بردار

همان کار برای `VITE_FEATURE_QUOTE_CUSTOMER_PICKER`.

**اثر:** قفل نام و شماره، دکمهٔ افزودن شماره، و قطع اتصال/اتصال دوباره می‌روند.
**نمی‌برد:** همان فهرست بالا. **`guestOverride` دیگر هرگز `true` نمی‌شود** چون تنها راه
`true`شدنش دکمهٔ گارد‌شده است — پس مسیر مهمانِ عمدی عملاً بسته می‌شود، ولی سندی که اصلاً مشتری
انتخاب نشده همچنان `guest_no_link` می‌گیرد.

### لایهٔ ۳ — همه‌چیز را بردار: revert کد

```powershell
git revert --no-commit <کامیت‌های این انتشار>
# سپس همان بیلد و استقرار
```

**تنها راه برداشتن** برچسب فهرست، فیلتر، نمایش استثنا، تلمتری و بن‌بست `guest_no_link`.

### و در دیتابیس، جدا از کد

```
۱. اول کد را به لایهٔ ۲ یا ۳ ببرید و rebuild کنید
۲. سپس بازگشت ۴۲۱ (فقط تابع)
۳. سپس بازگشت ۴۲۰ (فقط تابع؛ محدودیت گشاد بماند)
```

**ترتیب معکوس خطرناک است:** کدی که `guest_no_link` می‌فرستد به تابعِ برگردانده‌شده، رد می‌شود.
و **پیش از هر تلاشی برای باریک‌کردن محدودیت**، این را بزنید:

```sql
SELECT count(*) FROM public.sales_quotes WHERE quote_exception_type = 'guest_no_link';
```

ناصفر ⇒ **باریک نکنید**. بازنویسی یا حذف آن ردیف‌ها ممنوع است.

## جملهٔ آخر

> **بازگشت واقعی این انتشار «خاموش‌کردن یک پرچم» نیست.** خاموش‌کردن `GUEST_COMMITMENT` گام اجباری
> تازه را از ۷۶٪ کار برمی‌دارد و همان چیزی است که در نود درصد مواقع کافی است. خاموش‌کردن
> `CUSTOMER_PICKER` قفل هویت و مسیر عمدی مهمان را هم برمی‌دارد. ولی برچسب فهرست، فیلتر، نمایش
> استثنا، تلمتری و بن‌بست `guest_no_link` **هیچ کلیدی ندارند** — برداشتنشان یعنی `git revert` و
> rebuild. هر سه لایه به rebuild نیاز دارند، چون Vite مقدار پرچم را در زمان build جاسازی می‌کند.

`feature-flags.ts:69`. رفتار «خواندن هویت از پرونده» **اصلاً پیاده نشده** — کامنت خط ۳۶-۴۶ طوری
نوشته شده که خواننده باور کند پیاده است و منتظر داده. حذفش تاریخچهٔ تصمیم را پاک می‌کند؛
روشن‌کردنش هیچ اثری ندارد. تصمیم با مالک.
