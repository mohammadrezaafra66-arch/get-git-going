مطلقاً ممنوع:

\## آنچه باید کشف و گزارش کنی



\### بخش 1 — تصویر کلی شکاف

1\. دقیقاً چند commit و در چه بازه‌ی زمانی؟

2\. این commit ها عمدتاً از چه نوعی هستند؟ (قابلیت جدید، رفع باگ، migration، بازآرایی، مستندات) — یک تفکیک تقریبی بده.



\### بخش 2 — Migration ها (مهم‌ترین بخش)

3\. دقیقاً چند فایل migration در supabase/migrations روی شاخه‌ی feature هست که روی main نیست؟ لیست کامل با شماره.

4\. این حیاتی است — هر migration را دسته‌بندی کن:

&#x20;  - دسته الف — فقط ساختار: فقط جدول/ستون/تابع/trigger/index/constraint می‌سازد یا تغییر می‌دهد. داده‌ی موجود را لمس نمی‌کند. (امن برای اجرا روی تولید.)

&#x20;  - دسته ب — دستکاری داده: INSERT/UPDATE/DELETE روی ردیف‌های داده دارد. (خطرناک — ممکن است روی داده‌ی مشخص تست نوشته شده باشد، نه ساختار عمومی.)

&#x20;  - دسته ج — مختلط: هم ساختار هم داده.

&#x20;  برای هر migration در دسته ب و ج، دقیقاً بگو چه داده‌ای را دستکاری می‌کند و آیا به نظر می‌رسد مخصوص داده‌ی یک محیط خاص است یا عمومی.



\### بخش 3 — تفاوت بین وضعیت دیتابیس فعلی تولید و آنچه migration ها انتظار دارند

5\. با کوئری فقط SELECT روی دیتابیس تولید، بررسی کن: کدام‌یک از این migration ها احتمالاً از قبل (به شکلی) روی تولید اعمال شده و کدام‌ها واقعاً جدیدند؟

6\. آیا migration ای هست که فرض می‌کند داده یا ساختاری روی تولید وجود دارد که ممکن است نباشد؟ (ریسک شکست migration.)



\### بخش 4 — ریسک‌های خاص

7\. آیا کار نیمه‌تمامی در شاخه‌ی feature هست که نباید به تولید برود؟ به‌طور خاص چک کن:

&#x20;  - وضعیت حذف زیرسیستم invoices (سه شرط داشت — آیا کامل شده یا نیمه‌کاره؟)

&#x20;  - هر migration که در گزارش‌های docs/execution/\*-COMPLETE.md به‌عنوان «معلق» یا «نیاز به کار دستی روی تولید» علامت خورده

8\. آیا وابستگی جدیدی (npm، متغیر محیطی، سرویس خارجی) اضافه شده که تولید باید قبل از deploy داشته باشد؟

9\. تفاوت‌های محیطی: آیا فایل‌های .env، docker-compose، یا تنظیمات، فرض‌هایی دارند که بین تست و تولید فرق می‌کند؟ (پورت، رمز، نام کانتینر و غیره.)



\### بخش 5 — توصیه

10\. بر اساس همه‌ی بالا، یک ارزیابی صادقانه: آیا این شکاف برای انتقال یک‌جا آماده است، یا باید مرحله‌بندی شود؟ اگر مرحله‌بندی، پیشنهاد بده چطور.
