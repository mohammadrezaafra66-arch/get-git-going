## THE GATE — time-independent, which was the whole difficulty

At the moment this mission ran the window was **already shut** (`10:47` Tehran,
`inside_broken_window = f`). A gate that simply called the RPC would therefore have passed
against the *broken* code. It reconstructs the window instead:

```
     tz     | current_date_now | tehran_today | window_reconstructed
------------+------------------+--------------+----------------------
 Etc/GMT+12 | 2026-08-25       | 2026-08-26   | t
```

Under **both** regimes — `Etc/GMT+12` (the broken window) and `Asia/Tehran` (healthy) — it
asserts that today-in-Tehran is **accepted** and tomorrow-in-Tehran is still **rejected**
with `PURCHASE_DATE_FUTURE`, each behind a **vacuity guard** that fails if the regime was
not actually built. Plus structural checks on signature count, Persian integrity (36 HINT
occurrences over 31 distinct codes, no `?????` run), SECURITY DEFINER / VOLATILE / owner /
pinned `search_path` / the Persian COMMENT, and the ACL in both directions (`anon` must not
gain EXECUTE; `authenticated` must not lose it).

**Nothing is written.** Every probe goes through a `pg_temp` helper whose sub-transaction is
rolled back in both directions — including the accepted case, which raises its own marker to
force the rollback.
