# راهنمای تست دستی موارد 211 تا 218

این راهنما برای تست با کاربر login‌شده است. قبل از تست، DevTools را باز کنید و تب‌های Console و Network را نگه دارید. هیچ تستی را روی مشتری/پیش‌فاکتور واقعی حساس انجام ندهید؛ از داده تستی استفاده کنید.

## 211 — رد پیش‌فاکتور و اطلاع‌رسانی

Roleها:
- حسابدار یا مدیر برای رد
- همان کارشناس فروش صادرکننده برای مشاهده اعلان
- یک کارشناس فروش دیگر برای تست عدم دسترسی

URLها:
- `http://192.168.170.8:3100/sales/quotes`
- `http://192.168.170.8:3100/sales/quotes/$quoteId`
- `http://192.168.170.8:3100/notifications`
- `http://192.168.170.8:3100/my-rejected-quotes`

مراحل:
1. با کارشناس فروش یک پیش‌فاکتور تستی بسازید و به وضعیت `sent` برسانید.
2. با حسابدار وارد جزئیات همان پیش‌فاکتور شوید.
3. روی «رد» بزنید.
4. بدون نوشتن دلیل، دکمه تأیید باید غیرفعال باشد.
5. یک دلیل کامل بنویسید و رد را تأیید کنید.
6. صفحه را reload کنید و در جزئیات پیش‌فاکتور ببینید دلیل رد باقی مانده باشد.
7. با همان کارشناس فروش وارد شوید.
8. به `/notifications` بروید؛ اعلان `quote_rejected` باید دیده شود.
9. روی اعلان کلیک کنید؛ باید خوانده شود و به پیش‌فاکتور مربوط هدایت کند.
10. به `/my-rejected-quotes` بروید؛ دلیل باید نمایش داده شود.
11. با کارشناس فروش دیگر وارد شوید؛ نباید اعلان آن پیش‌فاکتور را ببیند.

انتظار:
- دلیل در refresh باقی بماند.
- notification تا read/mark باقی بماند.
- Console/Network خطای مرتبط نداشته باشد.

## 212-A — کنترل اعتبار پایه

Role: کارشناس فروش

URL:
- `http://192.168.170.8:3100/sales/quotes/new`
- `http://192.168.170.8:3100/sales/customers/$customerId/credit`
- `http://192.168.170.8:3100/accounting/dynamic-capital`

مراحل:
1. یک مشتری تستی با اعتبار قابل استفاده مشخص انتخاب کنید.
2. یک آیتم با مبلغ کمتر یا مساوی اعتبار بسازید؛ ثبت باید مجاز باشد.
3. همان مشتری را با مبلغ بیشتر از اعتبار تست کنید؛ popup کسری اعتبار باید نمایش داده شود.
4. متن popup باید مبلغ پیش‌فاکتور، اعتبار قابل استفاده و کسری را نشان دهد.
5. بدون انتخاب مسیر تعهد، ثبت عادی نباید انجام شود.
6. Network call مربوط به `create_sales_quote_with_items` باید در حالت غیرمجاز error بدهد.

## 212-B — مشتری معوق با تعهد فروشنده

Role: کارشناس فروش

مراحل:
1. مشتری تستی با وضعیت معوق انتخاب کنید.
2. پیش‌فاکتور بسازید.
3. سیستم باید popup «مشتری مانده معوق دارد» نشان دهد.
4. مقدار دقیقه را وارد کنید؛ مقدار مجاز 1 تا 240 است.
5. متن تعهد باید با همان N دقیقه ساخته شود.
6. روی «ثبت با تعهد کارشناس فروش» بزنید.
7. بعد از ثبت، جزئیات پیش‌فاکتور و دیتای quote را بررسی کنید که `quote_exception_type=overdue_salesperson_commitment` و متن تعهد ذخیره شده باشد.

انتظار ناقص فعلی:
- پیگیری deadline، اتصال فیش و وضعیت عدم ایفای تعهد فعلاً باید دستی بررسی/پیاده‌سازی شود.

## 212-C — بیش از اعتبار با تعهد کسری

مراحل:
1. مشتری با اعتبار مثبت اما کمتر از مبلغ پیش‌فاکتور انتخاب کنید.
2. ثبت عادی باید متوقف شود.
3. popup باید اعتبار قابل استفاده، مبلغ پیش‌فاکتور و کسری را نشان دهد.
4. روی «تعهد واریز کسری تا پایان روز» بزنید.
5. بعد از ثبت، `quote_exception_type=credit_shortfall_salesperson_commitment` و مبلغ کسری باید ذخیره شده باشد.

انتظار ناقص فعلی:
- سیستم پیگیری اتوماتیک پایان روز کاری و وصول کسری را کامل ندارد.

## 212.9 — مشتری فاقد اعتبار با تأیید حسابداری

مراحل:
1. مشتری فاقد اعتبار قابل استفاده یا مشتری مهمان را انتخاب کنید.
2. ثبت عادی باید متوقف شود.
3. popup باید مسیر «ثبت با تأیید حسابداری» را نشان دهد.
4. متن تعهد خانم ماهرو را بخوانید و ثبت کنید.
5. بعد از ثبت، `quote_exception_type=accounting_approval` و متن تعهد باید ذخیره شده باشد.

نکته:
- این تأیید فعلاً approval واقعی حسابداری نیست؛ فروشنده ادعا می‌کند تأیید گرفته است.

## 212.8 — کنترل موجودی

Roleها:
- کارشناس فروش برای ثبت
- مدیر/حسابدار برای قطعی‌سازی

مراحل ثبت:
1. کالایی با موجودی مشخص در یک انبار انتخاب کنید.
2. تعداد کمتر یا مساوی موجودی را تست کنید؛ ثبت باید ادامه یابد.
3. تعداد بیشتر از موجودی را تست کنید؛ popup موجودی باید باز شود.
4. popup باید نام کالا، تعداد درخواستی و موجودی فعلی را نشان دهد.

مراحل قطعی‌سازی:
1. پیش‌فاکتور `sent` را باز کنید.
2. روی پذیرش/قطعی‌سازی بزنید.
3. انبار را انتخاب کنید.
4. اگر موجودی کافی نیست، دکمه تأیید باید غیرفعال شود و پیام کسری نشان دهد.
5. اگر موجودی کافی است، قطعی‌سازی باید انجام شود.
6. بعد از reload، موجودی انبار و وضعیت پیش‌فاکتور را بررسی کنید.

ریسک تست:
- تست race condition باید در محیط کنترل‌شده و با دو درخواست همزمان انجام شود.

## 213 — امتیاز و اعتبار مشتری

Roleها:
- admin/accountant برای سرمایه و قوانین
- کاربر مجاز برای ورود امتیاز

URLها:
- `http://192.168.170.8:3100/sales/customers/$customerId/credit`
- `http://192.168.170.8:3100/accounting/dynamic-capital`
- `http://192.168.170.8:3100/sales/credit-rules`

مراحل:
1. یک کارشناس فروش فعال با پارامترهای امتیاز غیرصفر آماده کنید.
2. برای مشتری همان کارشناس، پارامترهای امتیاز را وارد کنید.
3. در `/accounting/dynamic-capital` برای امروز سرمایه روز ثبت و allocation را اجرا کنید.
4. به صفحه اعتبار مشتری برگردید.
5. امتیاز وزنی و سقف اعتبار باید غیرصفر شود، مگر binding constraint مثل overdue/no_salesperson/no_capital وجود داشته باشد.
6. یکی از scoreها را تغییر دهید و ذخیره کنید.
7. بدون ساخت snapshot دستی جدید، بعد از چند ثانیه/reload بررسی کنید اعتبار refresh شده باشد.

انتظار:
- اگر ledger مصرف سرمایه وجود داشته باشد، recompute باید skip شود و این رفتار باید در audit بررسی شود.

## 214 — گزارش واتساپ در market intelligence

Role: admin/manager/accountant

URL:
- `http://192.168.170.8:3100/pricing/market-intelligence`
- مبدأ: `http://192.168.170.8:3002/reporting`

مراحل:
1. صفحه مقصد را باز کنید.
2. بخش «محصولات پرتکرار در گفتگوهای واتساپ (مشتریان)» را پیدا کنید.
3. تعداد، رتبه، نام محصول، وضعیت، تعداد گروه، تعداد فرستنده و آخرین ذکر را با صفحه مبدأ مقایسه کنید.
4. روی «مشاهده فروشندگان اخیر» بزنید.
5. لیست فروشندگان/فرستندگان باید از API مبدأ بیاید.
6. 30 ثانیه صبر کنید یا صفحه را refresh کنید؛ تغییرات مبدأ باید در مقصد دیده شود.

Network:
- server function مقصد باید به `/api/v1/reporting/top-products` و `/api/v1/reporting/product-sellers` در سرویس 8002 متصل شود.

## 214.1 — Purchase Advisor

Role: کاربر مجاز صفحه operations

URL:
- `http://192.168.170.8:3100/operations/purchase-advisor`

مراحل:
1. محصولی را انتخاب کنید که در جدول واتساپ فروشنده/فرستنده دارد.
2. تعداد و فوریت را وارد کنید.
3. روی دریافت توصیه AI بزنید.
4. پاسخ باید شامل فروشندگان/فرستندگان اخیر واتساپ باشد.
5. محصولی را تست کنید که در واتساپ پیدا نمی‌شود؛ پاسخ باید صریح بگوید داده واتساپ ندارد.
6. محصول خارج کاتالوگ یا نام نزدیک را تست کنید و میزان تطابق را بررسی کنید.

انتظار:
- پاسخ نباید فروشنده خیالی بسازد.
- اگر داده فروشنده نیست، باید واضح بگوید پیدا نشد.

## 217 — تعریف ویزیتور

Role: admin یا manager

URL:
- `http://192.168.170.8:3100/admin/visitors`

مراحل:
1. وارد صفحه شوید.
2. روی «ویزیتور جدید» بزنید.
3. نام، کد اختیاری، تلفن اختیاری، ترتیب و وضعیت فعال را وارد کنید.
4. ذخیره کنید.
5. صفحه را reload کنید؛ ویزیتور باید باقی بماند.
6. ویرایش کنید و وضعیت را غیرفعال/فعال کنید.
7. با نقش غیر admin/manager تست کنید؛ نباید امکان مدیریت داشته باشد.

## 217.1 — انتخاب ویزیتور در پیش‌فاکتور

Role: کارشناس فروش

URL:
- `http://192.168.170.8:3100/sales/quotes/new`
- `http://192.168.170.8:3100/sales/quotes/$quoteId`

مراحل:
1. مطمئن شوید حداقل یک ویزیتور فعال وجود دارد.
2. فرم پیش‌فاکتور جدید را باز کنید.
3. فیلد «ویزیتور» باید نمایش داده شود.
4. یک ویزیتور متفاوت از ثبت‌کننده انتخاب کنید.

6. جزئیات پیش‌فاکتور را باز کنید؛ نام ویزیتور باید نمایش داده شود.

8. ویزیتور را غیرفعال کنید و دوباره فرم جدید را باز کنید؛ ویزیتور غیرفعال نباید در لیست انتخاب باشد.

## 218 — رسید اسکرین‌شات همراه بانک

Role: حسابدار یا admin

URLها:
- `http://192.168.170.8:3100/accounting/receipts/create`
- `http://192.168.170.8:3100/accounting/receipts`
- `http://192.168.170.8:3100/accounting/receipts/$receiptId`

مراحل:
1. صفحه ثبت فیش را باز کنید.
2. زیر گزینه‌های «پرفراژ دارد؟» و «فیش تایپی است؟»، گزینه «رسید اسکرین‌شات از همراه بانک است؟» باید دیده شود.
3. آن را تیک بزنید.
4. تصویر رسید را upload کنید.
5. فیش را ذخیره کنید.
6. جزئیات فیش را باز کنید؛ فیلد «رسید اسکرین‌شات همراه بانک» باید «بله» باشد.
7. صفحه فیش‌ها را باز کنید و خروجی اکسل بگیرید؛ ستون «رسید اسکرین‌شات همراه بانک» باید بله/خیر داشته باشد.
8. reload کنید و ماندگاری را تأیید کنید.

نکته:
- فیلتر اختصاصی برای این checkbox در لیست دیده نشد؛ فقط نمایش و خروجی اکسل وجود دارد.
