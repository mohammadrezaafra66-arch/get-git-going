می‌نشینند، بنابراین کامپوننت نمایش هیچ‌چیز پیدا نمی‌کند و ردیف‌ها خالی رندر می‌شوند.

## ۲ — یک نمونهٔ واقعی، سرتاسر

### آنچه کامیت‌ها گفتند

کامیت `24820547`:
```
Release-note-fa: در فرم تأمین‌کننده فیلد «کد آسان» اضافه شد تا بتوانید کد هر
تأمین‌کننده را ثبت کنید و خروجی آسان خرید برای او کار کند.
```

کامیت `a60e46d2`:
```
Release-note-fa: در صفحهٔ تأمین‌کنندگان هشداری اضافه شد که نشان می‌دهد چند
تأمین‌کننده هنوز کد آسان ندارند و با یک کلیک همان‌ها را فهرست می‌کند.
```

### آنچه در `platform_releases` نشست — نسخهٔ ۱۵

```
release_number | 15
title_fa       | 2 به‌روزرسانی جدید
summary_fa     | در این نسخه 2 تغییر اعمال شده است.
details_fa     | (NULL)
items          | [ { "sha": "a60e46d2", "text": "در صفحهٔ تأمین‌کنندگان هشداری ..." },
                 { "sha": "24820547", "text": "در فرم تأمین‌کننده فیلد «کد آسان» ..." } ]
```

**متن‌ها سالم‌اند.** ولی زیر کلید `text` نشسته‌اند، و عنوان و خلاصه جای‌نگهدارِ عمومی شده‌اند.

### آنچه کاربر می‌بیند

`PlatformReleaseCard.tsx:76-79`:

```tsx
{release.items.map((item) => (
  <li key={item.item_number} className="ms-1">
    <div className="font-medium">{item.title_fa}</div>
    <div className="text-muted-foreground">{item.description_fa}</div>
```

هر سه فیلدی که رندر می‌شوند — `item_number`، `title_fa`، `description_fa` — در دادهٔ
ذخیره‌شده **وجود ندارند**. نتیجه: عنوان کارت «۲ به‌روزرسانی جدید» و زیرش دو ردیف **خالی**.

`PlatformReleaseCard.tsx:17` بخش جزئیات را باز می‌کند چون `items.length > 0` است — پس
کاربر یک ناحیهٔ باز با ردیف‌های تهی می‌بیند، نه یک کارت جمع‌شده.

**چرا تازه دیده شد:** نسخهٔ ۱۴ فقط **یک** ورودی داشت، و در آن حالت عنوان و خلاصه خودِ متن
کامل می‌شوند (خط ۹۸ و ۱۰۲) — پس سالم به نظر می‌رسید. نسخهٔ ۱۵ **دو** ورودی داشت و
مسیر عمومی فعال شد.

## ۳ — علت دقیق

### علت اصلی — عدم تطابق قرارداد آیتم‌ها

`server/publish-release.mjs:110`:

```js
items: entries.map((e) => ({ text: e.title_fa, sha: e.shortSha })),
```

قرارداد در `src/lib/platform-releases/types.ts:3-10`:

```ts
export interface PlatformReleaseItem {
  item_number: number;
  title_fa: string;
  description_fa: string;
  module_key?: string | null;
  route_path?: string | null;
  change_type?: string | null;
}
```

publisher `{text, sha}` می‌نویسد؛ **هیچ‌کدام** از فیلدهای قرارداد را نمی‌نویسد. این پاسخ
مستقیم پرسش «چرا توضیح کامل نوشته نمی‌شود» است: `description_fa` اصلاً پر نمی‌شود.

### علت دوم — عنوان و خلاصهٔ عمومی برای انتشارهای چندموردی

`server/publish-release.mjs:98` و `:102`:

```js
const title = titles.length === 1 ? titles[0] : `${titles.length} به‌روزرسانی جدید`;
const summary = titles.length === 1 ? titles[0]
                                    : `در این نسخه ${titles.length} تغییر اعمال شده است.`;
```

وقتی بیش از یک ورودی باشد، تنها جایی که متن واقعی می‌ماند `items` است — که طبق علت اصلی
رندر نمی‌شود. دو نقص روی هم، کارت را کاملاً بی‌محتوا می‌کنند.

### علت سوم — `details_fa` هرگز پر نمی‌شود

`auto_publish_release` (مهاجرت ۳۰۷) اصلاً پارامتر `p_details_fa` ندارد:

```
p_git_sha, p_build_time, p_version, p_title_fa, p_summary_fa, p_category, p_items
```

پس فیلد توضیح بلند همیشه `NULL` است. **این رگرسیون نیست** — روی هر ۴ نسخهٔ دستی
(۱ تا ۴) هم `NULL` است. ولی یعنی جایی برای متن کامل وجود ندارد.

### چرا هیچ گاردی نگرفت

- RPC فقط `jsonb_typeof(p_items)='array'` و `jsonb_array_length >= 1` را بررسی می‌کند.
  **شکل آیتم‌ها اعتبارسنجی نمی‌شود**، پس آرایهٔ بدشکل بی‌صدا پذیرفته شد.
- اعتبارسنج واقعی `validateReleaseItems` در `src/lib/platform-releases/validate.ts:19-30`
  وجود دارد و `item.title_fa` را الزامی می‌کند — ولی فقط روی مسیر **پیش‌نویس دستی ادمین**
  اجرا می‌شود. مسیر RPC کاملاً دورش می‌زند.

### نقص جانبی — رقم لاتین در رابط فارسی

خط ۹۸ و ۱۰۲ از `${titles.length}` استفاده می‌کنند، پس «2 به‌روزرسانی جدید» تولید می‌شود
نه «۲». مخزن `toFaDigits` دارد.

## ۵ — رفع پیشنهادی (پیاده نشده)

### الف) شکل آیتم را با قرارداد هم‌تراز کن — ریشهٔ مشکل

در `composeRelease` (`server/publish-release.mjs:106-111`) آیتم‌ها با فیلدهای واقعی ساخته
شوند: `item_number`، `title_fa`، `description_fa`، و اختیاری `change_type` از نوع کامیت.

**یک تصمیم لازم:** امروز هر کامیت فقط **یک** جملهٔ فارسی دارد، پس `title_fa` و
`description_fa` هر دو همان می‌شوند. اگر عنوان کوتاه و توضیح بلند می‌خواهید، باید قرارداد
تریلر گسترش یابد — مثلاً یک `Release-note-fa-details:` اختیاری، یا پذیرش تریلر چندخطی.
این تغییر `AGENTS.md` و `CLAUDE.md` را هم لازم دارد.

### ب) عنوان انتشارهای چندموردی معنادار شود

به‌جای «N به‌روزرسانی جدید»، متن پرمعناترین ورودی به‌عنوان عنوان و بقیه در فهرست. یا
دست‌کم `summary_fa` فهرست کامل را بگیرد (سقف ۱۰۰۰ کاراکتر) تا نمایش به رندر `items`
وابسته نباشد.

### ج) گارد در مرز بگذار

`auto_publish_release` شکل آیتم‌ها را اعتبارسنجی کند و آرایهٔ بدشکل را **رد** کند. این
دقیقاً همان چیزی است که باید جلوی این نقص را می‌گرفت. نیازمند مهاجرت تازه.

### د) رقم‌های فارسی

استفاده از `toFaDigits` در متن‌های تولیدی.

### ه) عقب‌گرد داده‌ها — با یک مانع واقعی

نسخه‌های ۱۴ و ۱۵ متن درست را زیر کلید `text` نگه داشته‌اند، پس نگاشت
`{text} → {item_number, title_fa, description_fa}` بدون نیاز به گیت ممکن است.

**ولی** `trg_platform_releases_protect_published` ویرایش ردیف منتشرشده را ممنوع می‌کند و
فقط بایگانی را اجازه می‌دهد. پس عقب‌گرد یکی از این‌ها را می‌خواهد:

1. بایگانی ۱۴ و ۱۵ و انتشار دوبارهٔ محتوا با شکل درست (شماره‌های تازه می‌گیرند)، یا
2. یک مهاجرت که عمداً و مستند تریگر را برای همین اصلاح دور بزند.

گزینهٔ ۱ صادق‌تر است ولی شماره‌گذاری را می‌پراند. **تصمیم با مالک.**

## آنچه بررسی شد و سالم بود

- مولد `scripts/generate-release-notes.mjs` تریلرها را **درست** استخراج می‌کند؛ متن فارسی
  در `public/release-notes.json` کامل و بدون برش است.
- هیچ سقف طول یا برشی متن را کوتاه نکرده — `title.slice(0,200)` و
  `summary.slice(0,1000)` روی متن‌های فعلی فعال نشده‌اند.
- قاعدهٔ تریلر در کامیت‌ها **رعایت شده**؛ هر دو کامیت P2 تریلر درست داشتند.
- منطق «فقط موارد تازه» و idempotency درست کار می‌کنند.

یعنی هیچ‌کدام از چهار فرضیهٔ پرسش (برداشتن فقط خط اول، regex تنگ، برش طول، رعایت‌نشدن
قرارداد) علت نیستند. علت پنجمی است: **عدم تطابق قرارداد بین نویسنده و خوانندهٔ داده.**
