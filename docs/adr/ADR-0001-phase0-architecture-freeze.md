# ADR-0001 — قفل معماری فاز صفر افرا اتوماسیون

Status: Accepted  
Phase Label: PHASE-0  
Owner: محمدرضا افرا  
Date: 2026-06-05

## 1. زمینه تصمیم

پروژه افرا اتوماسیون / مولتی‌ربات افراکالا نباید به مجموعه‌ای از اسکریپت‌های پراکنده تبدیل شود. ریپوی فعلی `get-git-going` هم‌اکنون دستیار هوشمند افراکالا و هسته عملیاتی موجود است؛ بنابراین فاز صفر باید روی تثبیت همین هسته، قراردادها، جداول اتوماسیون، Worker Dummy و تست end-to-end متمرکز بماند.

## 2. تصمیم‌های پذیرفته‌شده

1. Laravel از فاز صفر حذف است.
2. ریپوی `get-git-going` تنها Control Plane / Core رسمی پروژه است.
3. Supabase/PostgreSQL منبع حقیقت داده‌های عملیاتی است.
4. React/TanStack/Lovable فقط لایه UI و پنل اپراتوری است.
5. Python Worker Runtime جدا از UI ساخته می‌شود.
6. Plugin/Driverها بیرون از UI و در Worker Runtime ساخته می‌شوند.
7. هیچ Core موازی، دیتابیس موازی، پنل موازی یا API موازی بدون ADR جدید مجاز نیست.
8. فاز صفر فقط شامل inventory، مستندسازی، جداول automation، Worker Dummy، API Contract و تست E2E است.
9. هیچ ربات واقعی در فاز صفر ساخته نمی‌شود: نه دیوار، نه واتساپ، نه اینستاگرام، نه ترب واقعی، نه OCR/STT و نه AI عملیاتی.

## 3. پیامدها

- هر Task Packet، PR و تغییر فنی باید به این ADR ارجاع بدهد.
- هر تغییری که معماری را عوض کند باید ADR جدا داشته باشد.
- Cursor و Lovable حق گسترش scope فاز صفر را ندارند.
- GitHub منبع رسمی تصمیم‌هاست و Drive فقط Mirror مدیریتی است.

## 4. کارهای ممنوع در فاز صفر

- ساخت ربات واقعی دیوار، واتساپ، اینستاگرام، ترب، OCR/STT یا AI.
- اضافه‌کردن Redis/RabbitMQ بدون ADR.
- ساخت backend جدید کنار ریپوی فعلی.
- ذخیره service role یا secret در مرورگر یا فرانت‌اند.
- ایجاد جدول‌های domain-specific برای botهای واقعی.

## 5. معیار پذیرش

این ADR زمانی پذیرفته‌شده محسوب می‌شود که:

1. در branch فاز صفر commit شده باشد.
2. در PR فاز صفر به آن ارجاع داده شود.
3. اسناد Source of Truth و Phase Label Policy با آن هم‌راستا باشند.
4. همه Task Packetهای فاز صفر عبارت «No real bot in Phase 0» داشته باشند.
