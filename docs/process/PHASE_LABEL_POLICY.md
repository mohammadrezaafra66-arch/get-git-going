Status: Active

## 1. هدف

این سند مشخص می‌کند هر سند، Task Packet، PR و تغییر کد باید متعلق به کدام فاز باشد. هدف اصلی جلوگیری از ورود زودهنگام ربات‌های واقعی به فاز صفر است.

## 2. برچسب‌ها

### BASELINE
وضعیت موجود و تأییدشده ریپوی `get-git-going` قبل از اجرای تغییرات جدید.

### PHASE-0
فقط شامل inventory، مستندسازی، جداول automation، API Contract، Worker Dummy و تست end-to-end است.

### PHASE-1
اجرای محدود و واقعی پس از تأیید فاز صفر. ورود تدریجی ماژول‌های کم‌ریسک مثل Google Maps محدود یا Torob محدود فقط بعد از approval.

### FUTURE
ربات‌های واقعی، مقیاس بزرگ، دیوار، واتساپ، اینستاگرام، OCR/STT، AI عملیاتی، صف‌های سنگین و runtimeهای پیشرفته.

## 3. قانون اجباری

هر سند، PR، issue، branch، task packet و module spec باید یکی از برچسب‌های بالا را اعلام کند.

## 4. نمونه‌های ممنوع در PHASE-0

- ساخت ربات واقعی دیوار.
- ساخت سندر واتساپ یا اتصال واقعی به واتساپ.
- ساخت استخراج‌گر واقعی اینستاگرام.
- ساخت استخراج‌گر واقعی ترب.
- اضافه‌کردن OCR/STT یا AI production.
- اضافه‌کردن Redis/RabbitMQ بدون ADR.
- ساخت backend یا API موازی.

## 5. نمونه‌های مجاز در PHASE-0

- تعریف جداول automation.
- تعریف OpenAPI contract.
- ساخت Worker Dummy بدون اتصال خارجی.
- ساخت صفحه ساده وضعیت command/run/status.
- تست E2E مسیر فرمان تا نتیجه.
- مستندسازی Runbook، DoR، DoD و PR Checklist.

## 6. معیار پذیرش

هیچ PR فاز صفر بدون اعلام Phase Label قابل merge نیست.
