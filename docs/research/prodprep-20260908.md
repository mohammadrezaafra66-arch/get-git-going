## The findings that outrank the tables

### A · Migration 460 will abort on production. Verified from the file.

460 addresses its rows by **hard-coded UUID**, and they are the **test** database's:

```
460 demands   : 0fbe576a-9ef3-475b-92e7-fabd981a7d5d  ·  d30816a9-8ff0-4d0e-8f25-0661f8cbea61
production has: f6a5bc04 (gpt)  ·  e07894ce (ollama)
```

It also carries four `RAISE EXCEPTION` guards — *"refusing to deactivate an unidentified provider"*.
**Those guards are correct behaviour.** Combined with hard-coded UUIDs they make the migration runnable
only on the machine it was written on. The rehearsal simulated the owner's manual OCR fix in its most
favourable possible form — even granting ollama the `vision` capability it lacks — and 460 still raised.

A further wrinkle recorded in the runbook: **correct UUIDs alone may not save it**, because
production's `ollama` provider does not declare the `vision` capability 460 requires.

### B · The ledger lies in BOTH directions

Migration **408** (`hold_credit_for_quote`) is absent from the baseline, sits **above** the 336–370
band, and **the ledger records it as applied**. So the ledger simultaneously under-reports (410–424
applied but unrecorded) and over-reports (408 recorded but not applied).

The sentence that matters, and it is in the runbook: **the ledger cannot be trusted in either
direction.** Anyone reasoning from it to decide what is outstanding will be wrong twice.

### C · The default privilege is a prerequisite, not a clean-up

Production carries **nine open `pg_default_acl` anon entries**. The test computer carries **zero** —
verified directly. That asymmetry is why this defect class is invisible on test, and why migration 507
passes there and fails on the rehearsal.

**26 of the 80 functions created by the successful migrations are born `anon`-EXECUTE-able**, including
`pay_purchase_with_voucher`, `review_credit_request` and `reverse_document`. Running the 74 without
closing the default first *manufactures* that exposure.

### D · Five migrations assert absolute row counts carrying test-only constants

410, 418, 449, 450, 452. They fail on any database that is not the test box — including a rehearsal
built from a real production dump. This is a **pattern**, not five coincidences: the correct form
asserts a *relationship*, not a number.
