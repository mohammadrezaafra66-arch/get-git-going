## 10 · Measurement traps found the hard way — read this before the next wave

**Three separate ways to get a confident FALSE ZERO in this repository.** Two of them produced wrong
findings inside this wave that had to be retracted.

1. **`git show 'origin/staging:<path>'` in Git Bash on Windows** mangles the colon path into
   `origin\staging;<path>`, the command fails, and a `grep -c` over the empty output returns **0**.
   This produced two wrong orchestrator findings — "ship.ps1 is not on staging" and "staging's
   .gitignore has no ship entries" — both false. **Read the file from a worktree's disk instead.**
2. **`vw_supplier_payables` and `vw_customer_receivables` return zero rows** to the `postgres`
   superuser without a JWT, and `authenticated` cannot select them at all — they are reachable only
   through `SECURITY DEFINER` RPCs. A zero read that way is a false negative, not a measurement.
3. **`npx tsc` in a worktree with no `node_modules` silently reports 0 errors** instead of failing
   (Agent Y's finding). An agent taking its baseline in a fresh worktree is handed a fake **0** and
   then appears to "raise" it to 70.

A fourth, not a false zero but a false pass: **`REVOKE EXECUTE … FROM anon` does not close anon.**
The grant comes from the bare `=X` PUBLIC entry `acldefault()` puts on every function. `REVOKE …
FROM PUBLIC` is required as well. Agent X caught this in its own first draft because its proof
checked `has_function_privilege` rather than assuming the REVOKE worked.

And a weak test worth naming: **grepping a view definition for a column name proves nothing.** After
Y-1, `cash_price` still appears in `vw_supplier_payables` — as an informational column. Only reading
the debt expression settles whether the fix landed.
