## What this runbook deliberately does NOT do

- **It does not use `mig_apply`.** `mig_apply` applies the SQL *and then* inserts the ledger row with
  no `ON CONFLICT` (`release/lib/mig-apply.sh:75-80`). Row `20260913090000` already exists on
  production, so that second step would fail with a duplicate-key error *after* the schema change
  had committed — a misleading "failure" on a successful apply.
- **It does not touch `supabase_migrations.schema_migrations` at all** — no INSERT, no DELETE. The
  row is already there; after Block 5 it becomes true. Migration 526 itself never writes the ledger:
  file lines 12-13 ("this migration gets a ledger row of its own ... WRITTEN BY THE OPERATOR'S
  mig_apply STEP AND NOT BY THIS FILE") and its final NOTICE ("This migration does NOT write
  supabase_migrations.schema_migrations"). Measured: ledger row count 696 before and after both
  rehearsal applies.
- **It does not change data.** Measured on the rehearsal: exact row counts of all 244 tables in
  `public`, `auth` and `supabase_migrations` identical before and after.
- It does not copy anything to the SMB share, build an image, or restart a container.

## Rules for the operator

1. Run each block in order in **one** PowerShell 5.1 window opened on the production laptop.
2. Compare the output to every `Expect:` line. **The first mismatch is a STOP.** Do not improvise a
   fix; report the block number and the full output.
3. Read `exit=` — never the colour of the text. Every psql call below redirects stderr inside the
   container (`2>&1` inside `sh -c`), so PowerShell should not print red NativeCommandError text;
   if it does, the `exit=` line is still the truth.
4. Do not type `$POSTGRES_PASSWORD` anywhere else, and do not print it. It is expanded *inside* the
   container by `sh`; PowerShell passes it through literally because every command is in single
   quotes.
5. **No double quotes inside the single-quoted `sh -c` strings.** PowerShell 5.1 mangles them when
   passing arguments to `docker.exe` — measured on the test computer: a `grep -E "a|b"` inside
   `sh -c '...'` returned 1561 instead of 23. Every command below was written without them and was
   run verbatim under PowerShell 5.1.26100 against the rehearsal database.
