# WPC-0-001 — Sample Phase 0 Task Packet

This is the canonical sample Task Packet for a documentation-only Phase 0 change.

It is a reference shape for future Phase 0 Task Packets. It remains documentation-only and does not authorize runtime code, migrations, secrets, external integrations, real bots, scraping, sending, OCR/STT, AI pipelines, browser automation, proxy/account automation, or production access.

## Background / goal

This sample packet demonstrates how to define a safe Phase 0 documentation task.

Sample scenario:

Update an approved governance document under `docs/automation/` to clarify Phase 0 documentation boundaries without changing runtime behavior.

The goal is to show the minimum information a reviewer needs before allowing a Phase 0 task to start and before accepting the delivered result.

## Phase label

`PHASE-0`

This packet is documentation-only.

## In-scope

- Review approved Phase 0 documentation.
- Update one approved Markdown document under `docs/automation/`.
- Keep the change governance-only or documentation-only.
- Preserve Phase 0 boundaries.
- Link relevant references.
- Update delivery evidence after completion.

## Out-of-scope / non-goals

- No runtime code.
- No executable commands.
- No migration SQL.
- No real credentials.
- No live external automation target URLs.
- No real bot instructions.
- No scraping workflow.
- No sending workflow.
- No AI/OCR/STT implementation detail.
- No browser automation guidance.
- No external integration.
- No production operational step.
- No parallel core, API, database, or admin panel.

## Stop-and-escalate conditions

Stop immediately and escalate if any of the following appear:

- Scope change touches runtime code.
- Scope change touches migrations.
- Scope change touches secrets or credentials.
- Scope change introduces real automation.
- Scope change introduces real scraping or sending.
- Scope change introduces browser automation.
- Scope change introduces AI/OCR/STT implementation.
- Scope change introduces external integration.
- Scope change introduces production-facing operational steps.
- Scope change creates or implies a parallel core, API, database, or admin panel.
- Reviewer cannot verify the result from the allowed files.
